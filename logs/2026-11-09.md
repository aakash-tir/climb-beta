# 2026-11-09

## Planned external training data: public datasets first, YouTube frames gated

**What we did:** Wrote `docs/plans/external-training-data.md` (#67) and filed
#68–#76. The plan compares public hold datasets with still frames from climbing
YouTube videos, defines a per-image source manifest that supports partial labels, and
sets the split and rights rules. No code changed, and this docs-only change needed no
architecture diagram update.

**The reason:** The first ~20 Basecamp photos were taken today. The owner proposed
adding empty-wall YouTube frames for hold-outline variety. Those frames have no usable
colour or tape labels, and the current pipeline has no record of which labels an image
carries. Nothing would stop an outline-only image reaching colour training, or a
non-Basecamp image reaching val or test.

**How it was solved:**
- **Recommendation:** public datasets now, YouTube frames only as a pilot. The pinned
  Roboflow set (#12) plus ClimbInst (#72) give ~3,000 labelled wall images for hours of
  work. A YouTube frame costs the same labelling time as a Basecamp photo but trains
  only outlines and can never be published. The pilot (#74) runs only if the first
  detector's Basecamp val errors show a gap, and frames stay only if they add ≥ 2
  points of Basecamp val hold recall.
- **Schema:** `manifest.jsonl` per built dataset, with `source`, `group`, `gym`,
  `label_scope` (exhaustive classes, class scheme, colour, start tape), `outline_only`,
  `ignore_regions`, `licence`, `publishable`, `allowed_splits` (#68). The key point:
  YOLO treats unlabelled pixels as background, so out-of-scope objects (like other
  gyms' tape) are blanked at build time instead of left unlabelled (#69).
- **Splits:** val and test are Basecamp-only and enforced (#68). External data is
  train-only. Training goes two-stage (#73) so ~3,000 external images don't drown a few
  dozen Basecamp photos, and so ClimbInst's merged hold+volume class can be used.
- **Rights:** YouTube frames are local-only: never in git, the HF dataset or the
  Space, and no video ids in committed files. Guards are in #70. Whether weights trained
  on them may ship is an owner decision in #74.
- **Evidence:** ClimbInst's card gives 1,509 images and 89,020 instances, SAM masks
  corrected by hand, one class, and no licence. A 2025 paper cites the `blackcreed`
  Roboflow set at 1,717 images and 63,897 annotations. Sources are listed in the doc.
